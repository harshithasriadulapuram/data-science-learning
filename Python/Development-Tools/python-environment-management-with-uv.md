
# Python Environment Management with uv

## 1. What Is uv?

`uv` is a fast Python tool for managing Python versions, virtual environments, project dependencies, and package installations.

It can replace several separate tools and workflows used in Python development.

Common uses:
- Creating and managing virtual environments.
- Installing dependencies.
- Managing Python project metadata.
- Locking dependencies for reproducible installations.
- Running Python scripts in managed environments.
- Installing and selecting Python versions.

## 2. Why Use uv?

Traditional Python projects often use:
- `venv` to create virtual environments.
- `pip` to install packages.
- `requirements.txt` to record dependencies.
- Additional tools for locking dependencies and managing Python versions.

`uv` provides a unified workflow for many of these tasks.

It is optional: Python's built-in `venv` and `pip` remain useful and widely supported.

## 3. Install uv

On Windows, one supported installation method is:

```powershell
powershell -ExecutionPolicy ByPass -c "irm https://astral.sh/uv/install.ps1 | iex"
```

On macOS or Linux, one supported method is:

```bash
curl -LsSf https://astral.sh/uv/install.sh | sh
```

These commands download and execute an installer. Review the installation instructions from the official uv documentation before running installation commands.

Verify the installation:

```bash
uv --version
```

## 4. Create a New Python Project

Create a project:

```bash
uv init my-project
cd my-project
```

A basic project may contain:

```text
my-project/
├── .git/
├── .python-version
├── main.py
├── pyproject.toml
└── README.md
```

The exact files depend on the initialization options and uv version.

### Understand the Important Files

- `main.py`: Example application entry point.
- `pyproject.toml`: Project metadata and dependency configuration.
- `.python-version`: Can specify the Python version selected for the project.
- `README.md`: Project documentation.
- `uv.lock`: Created when the project dependencies are resolved and locked.

Not every project needs every file.

## 5. Create a Virtual Environment

When working inside an initialized project, uv can create or manage its environment automatically.

To create one explicitly:

```bash
uv venv
```

By default, this creates a `.venv` directory.

Activate it on Windows PowerShell:

```powershell
.venv\Scripts\Activate.ps1
```

Activate it on macOS or Linux:

```bash
source .venv/bin/activate
```

You can also run project commands with uv without manually activating the environment.

## 6. Install Dependencies

For an initialized project, add a dependency using:

```bash
uv add requests
```

This updates the project's dependency configuration and lockfile.

Add a development dependency:

```bash
uv add --dev pytest ruff
```

Development dependencies are intended for development and validation rather than the application's normal runtime.

Install or synchronize the project's dependencies:

```bash
uv sync
```

The lockfile records a resolved dependency set so that installations can be reproduced more consistently.

## 7. Run Python Code

Run a script in the project environment:

```bash
uv run main.py
```

Run tests:

```bash
uv run pytest
```

Run Ruff:

```bash
uv run ruff check .
```

`uv run` makes it convenient to execute tools using the project's managed environment.

## 8. Manage Python Versions

uv can install Python versions and select them for projects.

For example:

```bash
uv python install 3.11
```

Select a version for the current project:

```bash
uv python pin 3.11
```

This can create or update the `.python-version` file.

Check which Python interpreter is running:

```bash
uv run python --version
```

Use a Python version supported by your project and its dependencies.

## 9. Understand `pyproject.toml` and `uv.lock`

### `pyproject.toml`

Contains project metadata, dependency declarations, and configuration for tools.

Example:

```toml
[project]
name = "my-project"
version = "0.1.0"
requires-python = ">=3.11"
dependencies = [
    "requests>=2.32",
]

[dependency-groups]
dev = [
    "pytest",
    "ruff",
]
```

This is an illustrative configuration. The exact metadata generated by uv may differ.

### `uv.lock`

Records the resolved versions of dependencies and relevant package information.

The two files have different roles:

- `pyproject.toml` describes what the project requires.
- `uv.lock` records a concrete resolved dependency set.

For an application, committing both files is usually helpful for consistent development and deployment.

## 10. Work With an Existing Project

If a project already has a `pyproject.toml`, you can use:

```bash
uv sync
```

To run a script:

```bash
uv run python main.py
```

If a project uses `requirements.txt`, uv can install those requirements into an environment:

```bash
uv pip install -r requirements.txt
```

The `uv pip` interface is useful when working with a traditional pip-compatible workflow. It is different from the project-oriented commands such as `uv add` and `uv sync`.

## 11. uv vs pip vs venv

| Tool | Main responsibility |
|---|---|
| `pip` | Installs Python packages |
| `venv` | Creates standard Python virtual environments |
| `uv` | Provides a faster, unified workflow for environments, dependencies, projects, and Python versions |

These tools are not mutually exclusive. A project can continue using `venv` and `pip` without adopting uv.

## 12. Common Mistakes

### Mistake 1: Committing the virtual environment

Do not commit `.venv/`.

Add this to `.gitignore`:

```gitignore
.venv/
__pycache__/
*.py[cod]
```

### Mistake 2: Forgetting the lockfile

For applications, committing `uv.lock` helps teammates reproduce the resolved dependency set.

### Mistake 3: Confusing `uv add` with `uv pip install`

- `uv add` declares a dependency in the project configuration.
- `uv pip install` installs packages using a pip-compatible interface.

Choose the workflow appropriate for the project.

### Mistake 4: Installing packages into the wrong environment

Run commands through the project's environment, for example:

```bash
uv run python -m pip --version
```

When possible, prefer `uv add` for project dependencies instead of manually changing the environment.

### Mistake 5: Assuming the lockfile guarantees identical behavior everywhere

Platform-specific dependencies, Python versions, operating systems, and external services can still affect behavior. Test on the environments you support.

## 13. Interview Questions

**Q1. What is uv?**

A Python tool that manages dependencies, virtual environments, project workflows, and Python versions.

**Q2. What is the difference between `uv add` and `uv sync`?**

`uv add` declares a dependency and updates the project configuration and lockfile. `uv sync` synchronizes the environment with the project's dependency specification and lockfile.

**Q3. What is `uv.lock`?**

A lockfile that records the resolved dependency set for more reproducible installations.

**Q4. Can uv replace pip and venv?**

It can handle many workflows provided by those tools, but pip and venv remain valid alternatives.

**Q5. Why use `uv run`?**

It runs a command in the project's managed environment, helping avoid confusion about which dependencies are available.

**Q6. Why should `.venv` not be committed?**

It contains a local environment that is machine- and platform-dependent. Dependencies should be declared so the environment can be recreated.

- uv provides a unified Python project and dependency workflow.
- Use `uv add` to declare dependencies in a managed project.
- Use `uv sync` to synchronize the environment.
- Use `uv run` to execute commands in the project environment.
- Keep `.venv` out of Git and commit the lockfile when appropriate.
